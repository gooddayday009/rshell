# RShell JumpServer 集成方案

- 目标发布版本：RShell 2.0.0（计划内容，尚未发布）。
- 文档状态：实施中；功能代码已接入，自动化及真实部署验证结果分别记录于 `STATUS.md`。
- 日期：2026-10-28。
- 首个兼容基线：JumpServer v4.10.2 社区版（用户已确认使用社区版）。
- 本次兼容范围：仅 JumpServer v4.10.2 社区版；其他版本不纳入本次交付。

## 1. 目标与范围

本方案的 JumpServer 集成纳入 RShell 2.0.0 版本计划，包括「选项 → JumpServer 堡垒机配置」、登录后自动同步授权资产到会话管理器的 JumpServer 目录，以及通过 JumpServer 中转连接 SSH 资产。RShell 2.0.0 是客户端目标发布版本，JumpServer v4.10.2 社区版是服务端首个兼容基线，两者独立记录。本方案不代表 RShell 2.0.0 的完整功能清单。

用户在 RShell 配置并登录 JumpServer 后，自动将当前用户有权访问的资产加载到会话管理器的 `JumpServer` 目录。双击资产，在 RShell 原生终端中建立连接，所有连接继续通过 JumpServer 中转，由 JumpServer 执行授权检查、目标账号登录和审计。

首期实现 SSH 资产连接、授权目录同步、账号选择、登录状态管理和异常提示。其他资产协议、SFTP、sz/rz、端口转发另行验证，不因 RShell 普通 SSH 已支持而视为中转场景已支持。

应用代码使用 Rust，保持 rshell-app、rshell-core、rshell-terminal 三层边界，不引入 Web 前端。

## 2. 版本兼容策略

以 v4.10.2 的实际 API、认证流程和 KoKo 行为为实现与验收依据。调研中的最新版文档与源码仅提供方向，不能代替 v4.10.2 验证。

| 版本范围 | 计划 | 当前状态 |
| --- | --- | --- |
| v4.10.2 社区版 | 登录、MFA、同步、SSH 中转完整闭环 | 代码已接入；真实部署验证待完成 |
| 其他版本 | 不纳入本次兼容范围 | 未验证 |

实现时将有差异的请求与响应转换集中在 JumpServer 适配模块。未知版本或未知响应应给出可诊断错误，不猜测字段、不退回目标主机直连。记录经过验证的准确版本、版本类型和认证方式。

首期功能以社区版可用能力为准，不依赖企业版或 X-Pack 专属接口与组件。用户确认的是版本类型和兼容基线，实际部署的准确版本仍需核实。

兼容基线不代表对该版本安全维护状态的背书。接入只使用当前用户授权的普通连接流程，不依赖管理员连接令牌或枚举其他用户令牌。

## 3. 用户操作流程

在顶部菜单「选项」中增加「JumpServer 堡垒机配置」入口，点击后打开同名原生配置窗口：

```text
选项
└─ JumpServer 堡垒机配置
```

配置窗口包含以下内容：

| 配置项 | 说明 |
| --- | --- |
| 实例名称 | 会话树中的名称，例如“公司堡垒机” |
| Web / API 地址 | 保留实际协议和端口，优先使用 HTTPS；截图提供的 HTTP 入口须确认实际 API 地址及传输条件 |
| KoKo SSH 地址和端口 | 可与 HTTPS 域名不同；端口初始提示 2222，可修改 |
| 登录方式 | 首先按实际环境验证账号密码流程；MFA、SSO 按实际流程适配 |
| 用户名和密码 | 账号密码登录时输入；密码掩码显示，不写入普通配置文件 |
| 组织 | 用户有多个可访问组织时选择 |
| 记住登录 | 可选，使用 Windows 凭据管理器保存允许持久化的认证信息 |
| 登录保持时间 | 默认 480 分钟，范围 1–43200 分钟；与服务端有效期取较短值，重启不延长绝对截止时间 |
| 一级／二级／三级默认账号 | 在当前授权账号中依次精确匹配目标用户名或账号别名；歧义或无匹配时由用户选择 |
| 自动同步 | 登录后立即同步，启动后在认证有效时同步，默认每 60 分钟刷新，可在配置窗口调整为 1–43200 分钟，保存后重新计时 |

窗口提供「保存配置」「登录并同步」「立即同步」「退出登录」「关闭」操作。「保存配置」仅保存配置，不代表登录成功；「登录并同步」完成认证后自动加载授权资产；「立即同步」仅在已登录且未同步时可用。关闭窗口不等于退出登录。

窗口显示当前登录用户、所选组织、登录状态、同步状态、上次成功同步时间和可见错误信息。MFA 或审批按服务端响应进入对应交互。

配置表单按连接信息、登录设置、资产同步分区；默认连接账号可折叠，主要操作和同步状态位于表单滚动区域外。服务端要求 MFA 时自动弹出独立模态窗口，聚焦验证码输入框，支持回车验证、短信/邮件发送验证码及取消认证。失败在弹窗内提示；取消时停止请求并清除验证码，重新登录后发起新挑战。

操作流程：选项 → JumpServer 堡垒机配置 → 登录并同步 → 完成必要认证 → 选择组织 → 自动加载资产 → 双击资产 → 选择授权账号 → 建立中转连接。

会话树示例：

```text
会话管理器
├─ 我的会话
└─ JumpServer
   └─ 公司堡垒机
      └─ 当前组织
         ├─ 生产环境
         │  ├─ order-api-01
         │  └─ worker-01
         └─ 测试环境
            └─ test-api-01
```

优先保持 JumpServer 的授权节点结构。SSH 资产可连接；其他协议标明暂不支持。支持按名称、地址搜索，右键刷新和查看连接详情。界面显示登录状态、同步状态、上次成功同步时间。

受管目录和会话不能直接修改目标地址，不能通过拖拽、复制或导出变成绕过中转的普通会话。现有本地会话按原有方式管理。

## 4. 授权资产同步

仅查询当前登录用户的有效授权资产、节点、协议与账号，不使用管理员全量资产接口，也不获取托管账号密码。

v4.10.2 授权节点接口会返回 ID 为 `favorite`、`ungrouped` 的虚拟分类。客户端识别并排除它们的目录关系解析，保留真实 UUID 节点和完整授权资产；收藏分类不在本地复制，无可见目录归属的资产进入本地「未分组资产」。不得因虚拟分类导致整批同步失败，也不得忽略其他非法真实节点 ID。

授权资产的 `nodes` 使用 v4.10.2 `ObjectRelatedField` 输出的 `{id, name}` 对象数组；客户端提取并严格验证其中的 UUID，同时兼容本地缓存的 UUID 字符串数组。接口回归数据须使用对象形式，不能仅用本地结构序列化的缓存格式替代服务端响应。

以“实例 ID + 用户 ID + 组织 ID + 资产 ID”作为资产身份；节点使用服务端节点标识。名称、IP 仅用于展示，避免同名、同 IP 或改名造成误匹配。同一资产属于多个节点时，目录引用共享同一个资产身份。

同步规则：

1. 分页获取，在后台设置请求超时、并发限制、响应大小及资产数量上限。
2. 所有必要页面成功后原子更新快照；达到上限或部分请求失败时不得当作完整成功。
3. 新增、改名、移动按稳定标识更新，重复刷新不产生重复资产。
4. 完整同步确认删除或撤权后移除对应受管条目；不删除用户自己的本地会话。
5. 同步失败保留最后成功缓存并标明过期状态，不能将失败结果当作空资产列表覆盖。
6. 切换用户、组织或退出登录时取消旧请求，丢弃迟到结果，隔离不同身份的缓存。
7. 缓存仅用于展示。每次连接仍由服务端检查权限；离线缓存不能授权新连接。

同步请求不得将登录凭据随跨站重定向或未经校验的分页地址发送到其他来源。

## 5. 中转连接设计

```text
RShell ── HTTPS ──→ JumpServer API
                   认证、授权资产、申请连接

RShell ── SSH ────→ KoKo ──→ 目标服务器
                   授权、代理与审计
```

优先验证 v4.10.2 的普通临时连接令牌流程：

1. 双击资产，查询该资产当前允许的账号、协议和连接方式。
2. 单个授权账号直接使用；多个账号按设置中的一级、二级、三级默认账号顺序精确匹配目标用户名或账号别名，仅唯一匹配时自动使用。没有匹配或存在歧义时由用户明确选择，不能预选列表首项充当默认账号。不隐式优先 root；用户明确配置 root 且授权匹配时可以使用。需要本次输入凭据的账号仍显示输入窗口。
3. 按服务端要求处理连接审批或二次认证。
4. 申请本次连接凭证，按 v4.10.2 KoKo 源码使用 `JMS-{id}` 用户名和 `value` 作为一次性密码。
5. 使用配置窗口中明确填写的 KoKo 主机及端口，交给现有 SSH 引擎连接；资产 IP 仅作展示，不作为网络连接入口。
6. 在 RShell 终端中展示目标会话，标签使用资产名称，详情显示目标账号和实际中转入口。
7. 失败、取消和过期按服务端语义处理；重连重新申请凭证，不永久缓存临时连接令牌。

官方复合 SSH 用户名方式可作为明确验证后的兼容模式：

```text
ssh -p 2222 JumpServer用户@资产账号@资产IP@JumpServer入口
```

该模式仍连接 JumpServer，但同 IP 多资产、特殊用户名及交互认证需单独处理。首期不自动输入菜单序号选择资产，不依赖终端输出文本驱动本机操作。若临时令牌流程在实际环境不可用，应明确提示或使用已配置且验证过的兼容模式。

任何连接失败都不得自动退回直连目标 IP。最近连接、重连、复制会话等入口必须保留 JumpServer 来源与资产引用。

## 6. 认证与凭据

区分 JumpServer 登录凭据、API 登录令牌和单次 SSH 连接凭证，不能互相当作长期会话密码使用。

- 默认仅在内存保留登录状态；用户选择记住登录后，按项目规范使用 Windows 凭据管理器。
- 登录保持时间可配置，实际截止时间取“本次登录时间 + 保持时长”和服务端令牌截止时间的较短值。持久化保存绝对截止时间，重启不续期；缩短设置立即约束现有登录，延长设置重新登录后生效。到期清理认证状态并要求重新完成密码与 MFA，不能自动绕过认证续期。
- 单次连接凭证不写入 JSON、导出文件、日志、命令行参数或剪贴板。
- 不下载和保存目标服务器的托管密码、私钥。
- 登录过期后提示重新认证，不无限重试密码，不用关闭 MFA 或审批解决兼容问题。
- HTTPS 使用证书校验；内网 CA 通过受信任证书配置支持，不提供无条件跳过验证的默认路径。
- SSH 校验 KoKo 主机密钥：首次自动保存并继续，已记录密钥变化时阻断。
- 退出登录清理本地认证状态、已保存登录凭据及待连接任务；已有活动终端的处理应在界面明确说明，并提供断开操作。
- 已有会话的撤权终止由 JumpServer 服务端策略决定，不能宣称同步列表即可立即终止服务端会话。

当前 RShell SSH 仅有密码和私钥认证分支，交互式 MFA 需补充。现有凭据模块使用 DPAPI 文件，与项目规范要求的 Windows 凭据管理器存在差异；新增 JumpServer 凭据按规范实现，既有凭据迁移不隐含纳入本次范围。

SSO 应先验证该部署可用的官方客户端授权流程。不能假定网页登录完成后 RShell 自动获得 API 登录状态，也不能读取浏览器 Cookie 作为通用登录方案。

## 7. 模块与数据设计

| 层级 | 改造职责 |
| --- | --- |
| rshell-app | 「选项 → JumpServer 堡垒机配置」菜单及窗口、受管会话树、账号选择、认证挑战、同步与连接状态 |
| rshell-core | JumpServer API、认证状态机、版本适配、分页同步、缓存隔离、连接参数解析 |
| rshell-core SSH | 接收临时参数、校验 KoKo 主机密钥，按需补充交互认证 |
| rshell-terminal | 复用现有终端显示与输入能力，保留容量边界 |

建议增加以下概念，具体类型在实施时确定：

- `JumpServerConfig`：实例 ID、地址、SSH 入口、同步选项与选定组织。
- `JumpServerAssetRef`：实例、用户、组织、资产及节点引用。
- `JumpServerSnapshot`：最后一次完整同步的资产元数据与时间，不含秘密。
- `ResolvedConnection`：仅用于本次连接的入口、用户名和临时凭证，不序列化保存。

JumpServer 是会话来源与连接方式，SSH 仍是传输协议。不要仅将资产 IP 填入现有普通 SSH Profile。保存的资产引用与运行时解析出的实际入口必须区分。

网络、磁盘、凭据读写均在后台执行。任务支持取消，返回结果携带身份与请求代次，防止切换配置后旧结果覆盖新状态。

## 8. 实施步骤

### 阶段一：验证 v4.10.2 接口与连接闭环

确认实际版本类型、认证方式、组织、API 权限及 KoKo 入口。对照 v4.10.2 源码和实际接口文档核实认证、授权列表、账号与连接凭证流程。使用测试用户和测试资产验证，不连接生产服务器进行自动化测试。

交付：准确的接口字段与错误状态记录，以及一个真实中转连接验证结果。未经验证的认证方式继续标为待完成。

### 阶段二：配置与会话目录同步

完成登录配置、凭据存储、后台同步、受管目录、搜索、刷新、缓存隔离和错误展示。

交付：登录后自动加载当前用户资产，重复同步无重复条目，失败不破坏最后成功快照。

### 阶段三：原生终端连接

完成账号选择、临时连接参数解析、KoKo SSH 连接、重连及身份展示。按实际部署补充 MFA 或审批交互。

交付：双击授权 SSH 资产打开 RShell 终端，并在 JumpServer 核实会话身份和审计结果。

### 阶段四：验收与后续版本适配

执行项目检查、针对性 GUI 验证和真实 v4.10.2 端到端测试。其他版本不纳入本次交付。README 与 docs/STATUS.md 分别记录已实现、已验证、待完成。

| 场景 | 预期结果 |
| --- | --- |
| 配置入口 | 从「选项 → JumpServer 堡垒机配置」打开配置窗口，可保存配置、登录并同步、查看状态及退出登录 |

| 同名、同 IP 资产 | 按资产 ID 区分，连接不误选目标 |
| 多授权账号 | 用户明确选择账号，界面展示实际身份 |
| 双击连接 | 通过 KoKo 进入目标资产，网络连接目标不变成资产直连地址 |
| 审计核验 | JumpServer 中用户、资产、账号正确，命令审计和录像符合服务端配置 |
| 登录或连接令牌过期 | 明确提示认证或重新申请，不复用无效凭据循环连接 |

| MFA / 审批 | 按服务端流程执行；未适配时明确提示，不绕过 |
| 撤权、资产删除 | 完整同步后条目更新，新连接由服务端拒绝 |
| 同步中断或分页失败 | 保留旧快照并提示失败，不误判资产被删除 |
| 用户或组织切换 | 缓存隔离、旧请求取消，不混入旧身份结果 |
| KoKo 主机密钥变化 | 阻断连接并提示，不无条件接受 |
| 凭据检查 | JSON、日志、导出文件、命令行参数中无敏感凭据 |
| 普通本地会话 | 原有创建、连接、目录管理能力不受影响 |

交付前运行 `scripts/test.ps1`，凭据相关变化补做 `-WithCredentials`，窗口变化进行针对性 GUI 验证；发布、打包或用户明确要求时再运行整套 `-Smoke`。本机回环 SSH 测试与模拟 API 测试不能代替真实 JumpServer 和 Linux/OpenSSH 兼容验证。

## 11. 调研依据与证据边界

### 全局默认账号候选接口（2026-10-28）

核对本地 v4.10.2 源码 `apps/perms/urls/user_permission.py`、`apps/perms/api/user_permission/assets.py` 与 `apps/perms/serializers/user_permission.py`：用户授权路由未提供全局账号列表；`GET /api/v1/perms/users/self/assets/` 提供分页资产列表，`GET /api/v1/perms/users/self/assets/{id}/` 返回 `permed_accounts`、`permed_protocols`。不使用需要授权规则管理权限的 `asset-permissions/{id}/accounts/` 接口。

配置窗口不要求选择资产。用户点击「加载 / 刷新授权账号」后，后台依次查询当前组织的有效授权资产详情，只汇总允许 SSH 且具有 connect 权限的用户名与账号别名，排序去重供三个全局优先级选择。任一请求失败则整次加载失败，不返回部分候选；整体超时 180 秒，允许取消。资产较多时可能超时，性能仍需现场验收。候选不代表对其他资产的授权，连接时保留原有三级精确匹配及实时授权校验。旧配置值保留，每级可以清空为「不指定」。

### 可选密码与自动重认证（2026-11-01）

已实现：独立的 `remember_password` 开关，默认关闭；密码与令牌分别存入 Windows 凭据管理器，后台读写，JSON 只记录开关。启用后在无有效启动令牌、到期、API 401 时尝试密码认证，需要 MFA 时弹窗，审批按原流程处理。认证失败停止自动尝试；取消勾选并保存、身份切换、退出登录删除对应密码。密码框留空不覆盖已保存密码。

重连在认证后继续，并校验原实例、用户、组织、资产和账号；原账号不可用或歧义时停止。已建立的 SSH 会话异常报错断开后尝试一次新连接，正常退出、主动断开和初次连接失败不触发；排队上限 20，退出登录、取消认证或切换身份清空队列。不会重放命令。已有健康终端不会因 API 登录到期而被主动断开。

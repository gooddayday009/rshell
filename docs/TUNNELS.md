# SSH 隧道

支持普通 SSH 会话的本地转发、远程转发和 SOCKS5 动态代理，全部使用 Rust / russh 实现。网络操作在后台执行，不调用本机 ssh 命令，不通过远端 Shell 拼接命令。JumpServer 专用连接流程、Telnet 和串口不启用本功能。

## 配置与连接

1. 从“文件 → 新建 SSH 隧道连接…”新建仅隧道会话，填写 SSH 主机、端口、用户名及登录方式。也可编辑已有 SSH 会话。
2. 在左侧选择“SSH 隧道”，添加规则，选择类型，填写监听地址和端口；本地/远程转发还需填写目标地址和端口。
3. 勾选“仅建立隧道，不打开远程终端”时，服务器无需提供 PTY 或 Shell。取消勾选后，隧道与交互终端一同运行。
4. 点击“保存并连接”。首次连接仍走原有主机密钥保存流程；已记录主机密钥变化仍阻断连接。
5. 标签页显示各规则的状态及最近转发连接错误。使用工具栏“断开连接”停止全部隧道，“重新连接”按该标签的配置重新建立连接。修改已保存规则需重新打开该会话或在重连设置中修改后连接，运行中的规则不会被静默替换。

| 类型 | 监听位置 | 目标连接由谁发起 | 示例 |
| --- | --- | --- | --- |
| 本地转发 | 本机 | SSH 服务端 | 本机 `127.0.0.1:13306` → 服务端访问 `db.internal:3306` |
| 远程转发 | SSH 服务端 | 本机 | 服务端 `127.0.0.1:18080` → 本机访问 `127.0.0.1:8080` |
| 动态 SOCKS5 | 本机 | SSH 服务端 | 应用代理设为 `127.0.0.1:1080`，选择代理端解析域名 |

“127.0.0.1”表示所在一侧的回环地址；本地转发的目标地址属于服务端视角，远程转发的目标属于本机视角。目标主机支持域名、IPv4、IPv6；IPv6 输入不带方括号。监听地址须为明确的 IPv4/IPv6 地址，不使用 `localhost` 别名。端口范围为 1–65535，不支持自动分配监听端口。

## 行为与限制

- 默认监听 `127.0.0.1`。普通端口转发可以显式设置其他监听 IP，界面会提示外部可达范围；远程监听的实际范围和许可由 SSH 服务端策略决定，RShell 不修改服务端配置。
- SOCKS5 支持无认证 TCP CONNECT、IPv4、IPv6、域名原样传给 SSH 服务端解析；只允许回环监听。不支持 SOCKS4、UDP ASSOCIATE、BIND 或代理账号认证。协议参考 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)。
- 每个会话最多保存 16 条规则；最多同时处理 64 个转发连接，待处理队列有界。超额新连接会被关闭。连接目标、SSH 通道建立和 SOCKS5 握手均设 15 秒超时；已建立的数据流不设空闲超时，使用 SSH 会话的保活设置。
- 只有 SSH 认证成功后才开始监听。启动采用整体成功策略：端口占用、远程转发被拒绝或其他规则启动失败时，本次 SSH 连接失败，已建立的本地监听和数据流会关闭，并请求服务端取消远程监听。运行中单个目标不可达只关闭该数据流，保留监听，并显示最近错误。
- 断开、关闭所属标签、终端退出或网络连接结束会停止该标签的隧道。远程监听取消有有限等待；最终远端清理由 SSH 服务端处理。服务端无响应时网络故障检测还受 SSH 保活配置影响。
- “复制 SSH 渠道”只创建终端渠道，不复制监听规则；原标签仍拥有其隧道，原标签关闭后隧道停止。仅隧道标签禁用渠道复制、终端输入和 AI 命令执行。复制整个会话会尝试重新绑定相同端口，可能因端口占用失败。
- 规则随配置保存，旧配置默认无隧道。`.rsh` 导入导出保留规则，含隧道的单会话使用版本 3，需要支持该功能的 RShell；普通会话保持版本 1、集合外层保持版本 2。Xshell `.xts` 导入导出当前不传递隧道规则。

## 验证边界

本机 russh 回环测试覆盖实际 TCP 数据转发及资源清理，不等于 Linux/OpenSSH、真实公网网络或生产堡垒机已验收。真实 OpenSSH 的 AllowTcpForwarding / GatewayPorts / PermitOpen 等策略组合、长时间运行和网络故障场景仍需独立验收。当前状态见 [STATUS.md](STATUS.md)。
